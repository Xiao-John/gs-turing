# 模型与求解器

## 1. 模型

标准 Gray–Scott 模型（无量纲）：

```
u_t = Du ∇²u − u v² + f (1 − u)
v_t = Dv ∇²v + u v² − (f + k) v
```

- `u`：食物/基质浓度，由供给项 `f(1−u)` 补充
- `v`：自催化产物，`u v²` 是自催化项，`(f+k) v` 是冲刷项
- 默认参数：`Du = 0.16`、`Dv = 0.08`

### 1.1 带资源场的推广（`core/gs.py`）

```
u_t = Du ∇²u − u v² + f (u_res(x,y,t) − u)
v_t = Dv ∇²v + u v² − (f + k) v
```

`u_res ≡ 1` 时退化回标准模型。**驱动只能加在 `u_res` 上**：

> 不要把空间结构加到 `f` 上。改 `f` 会同时改变供给速率 `f·u_res` 和冲刷速率 `(f+k)v`，
> 一个"随位置变化的 `f`"根本不是供给场，它的语义是混的。`u_res` 只有一个含义：
> 该点被补充到的目标浓度。

`u_res` 必须处处非负，且有限；求解器在每次取值时检查，不合法就报错而不是继续跑。

### 1.2 可用的稳定斑点（实测，不是估计）

当前工具链验证过的**孤立稳定斑点**：

```
Du = 0.16,  Dv = 0.08,  f = 0.055,  k = 0.066
种子：14x14 方块，u = 0.5, v = 0.25（经典 Pearson 种子）
```

| 量 | 值 |
|---|---|
| `Mv = h²Σv` | 19.841 |
| `vmax` | 0.4044 |
| 回转半径 `Rg` | 2.947 |
| 连通分量数 | 1 |
| 中心 `(u, v)` | (0.298, 0.400) |
| 再演化 `t = 10⁴` | `max|Δv| = 0.000` |

它是**精确平衡态**，不是慢瞬变。这两个常量在代码里是
`core.gs.STABLE_SPOT_F` / `STABLE_SPOT_K`。

> **注意：`f = 0.038, k = 0.068` 不能成核。** 用同一个 14×14 种子，v 在 `t ≈ 200`
> 之前就衰减到 0。一个衰减掉的场会让所有下游比较变得空洞（到处都是 0，
> 任何"一致性检查"都会通过），所以任何以斑点为前提的检查都必须先确认 `vmax > 0`。
> 附近参数也不等价：`(0.050, 0.066)` 稳定到 `t ≈ 20000` 后自复制成 16 个分量，
> `(0.060, 0.064)` 在缓慢长大。

### 1.3 晕尺度：真正的设计约束

v 的核心很小，但 u 的亏空延伸得很远：

| 判据 | 元胞数 | 最大半径 | 等面积半径 |
|---|---|---|---|
| `v > 0.05` | 80 | 5.7 | 5.05 |
| `v > 0.01` | 120 | 6.7 | 6.18 |
| `1-u > 1e-3` | 540 | 13.6 | 13.11 |
| `1-u > 1e-5` | 1340 | 21.2 | 20.65 |
| `1-u > 1e-7` | 2504 | 28.9 | 28.23 |

**v 核心 ~5 格，u 亏空 ~29 格。** 斑点之间通过 u 场远距离耦合，所以位点间距
必须按 u 晕的作用尺度定，而不是按 v 看起来的大小定。这直接限制了纸带密度，
也是 `docs/04_research_plan.md` §3.3 里"写入选择性"问题的来源。

## 2. 两个求解器，各自负责什么

| | `core/solver.py` | `core/gs.py` |
|---|---|---|
| 定位 | 参考实现（ground truth） | 高通量求解器 |
| 边界条件 | periodic / noflux / reservoir / dirichlet | 仅 periodic |
| 不可渗透壁 | 支持（`active` 掩码） | 不支持 |
| 参数场 | 支持（`param_field` 传 f/k/Du/Dv 数组） | 不支持 |
| 资源场 `u_res` | 不支持 | 支持（含时间依赖） |
| 时间路径 | 显式 Euler | 显式 Euler + 谱 IMEX |
| 后端 | C kernel（`cc` 编译）或 numpy | 纯 numpy/FFT |
| 速度 | C 后端最快 | IMEX 大步长时最快 |

**分工理由**：`solver.py` 保留通用性——边界规则、壁面、异构参数的逻辑只写一次；
`gs.py` 用通用性换速度和一等公民的驱动场。两者在 `u_res ≡ 1`、periodic、同参数、
同步长下必须给出同一个离散演化，这一点由 `verify/check_solvers.py` 的 C2 检查守着。

**参数默认值不同是故意的**：`solver.py` 用 `f=0.035, k=0.065`，`gs.py` 用 `f=0.038, k=0.068`。
比较两者时必须显式传 `f`、`k`，否则你比的是两个不同的模型。

## 3. 两条时间路径（`core/gs.py`）

### 3.1 显式 Euler

5 点 Laplacian，同步更新（`u_new` 与 `v_new` 都用旧场），float64，无裁剪、无死亡阈值、无噪声源。

稳定性护栏是**硬错误**，不是警告：

```
dt · max(Du, Dv) / h² ≤ 1/4
```

历史上有一条这样的运行静默违反了它，十几步后停住，而那条冻结的 trace 被读成了
"结构没有移动"。现在违反它直接 `ValueError`。

### 3.2 谱 IMEX

线性部分在 Fourier 空间精确求解，非线性部分显式：

```
[1 + dt·Du·|q|² + dt·f]      û* = û + dt (f·û_res − F[uv²])
[1 + dt·Dv·|q|² + dt(f+k)]   v̂* = v̂ + dt F[uv²]
```

- `spectral_lap=True`：符号用 `−|q|²`（真正的谱扩散）
- `spectral_lap=False`：符号用 5 点格式 `−(4/h²)[sin²(qx h/2) + sin²(qy h/2)]`

**这两者是不同的求解器，记录里会分开标注。** 想看"细化 dt 后 IMEX 是否逼近显式解"，
用 `spectral_lap=False`；`spectral_lap=True` 是另一个离散化，不该期望它在有限 dt 下收敛到同一条离散轨迹。

### 3.3 ⚠️ `dealias=True` 不能用于长时间定量工作

`dealias=True` 时对三次项 `uv²` 用 2/3 规则（掩码由采样频率构造，不是由 `−|q|²` 符号构造）。
**实测结论：它会引入一个不随 `dt` 减小的负向欠冲。**

在 `dt=0.25`、`t=50`、光滑种子、`n=128` 下测得：

| 配置 | `t=50` 的 `vmin` |
|---|---|
| `spectral_lap=False, dealias=False` | `-5.6e-16` |
| `spectral_lap=False, dealias=True` | `-2.9e-04` |
| `spectral_lap=True,  dealias=False` | `-3.5e-07` |
| `spectral_lap=True,  dealias=True` | `-2.0e-04` |

`dealias=False` 配 5 点符号时干净到机器精度；一旦打开去混叠就出现 `~1e-4` 的负值，
而且**细化 `dt` 不会改善**（`dt` 从 1 到 0.05，`t=50` 的 `vmin` 从 `-9.6e-05` 变到 `-2.3e-04`，
反而略差）。原因很清楚：这是**空间截断**误差（2/3 掩码切掉了三次项的高波数成分，
产生 Gibbs 振铃），时间步长不可能修好它。

**因此默认必须是 `dealias=False`。** 该选项保留下来以便对比，而不是为了使用它。
健康检查会在欠冲超过容差时把运行标为 `failed`——那是关于解的真实陈述，不是需要调掉的噪音。

IMEX 没有显式扩散步长限制——这正是它在长时间演化上的用处。

## 4. 边界条件与固定元胞

`core/solver.py` 支持四种边界规则，通过 `bc` 选择：

| `bc` | 邻居规则 | 每步之后 |
|---|---|---|
| `periodic` | 索引回绕 | — |
| `noflux` | 域外邻居取自身（零通量） | — |
| `reservoir` | 同 noflux | 把最外一圈钉在 `u=1, v=0` |
| `dirichlet` | 同 noflux | 把 `fixed_mask` 指定的元胞钉在 `u=1, v=0` |

壁面用 `active` 掩码表达（1 = 反应元胞，0 = 不可渗透壁）。落在壁里的邻居被替换成元胞自身，
于是穿过该边的扩散通量为零。壁元胞在每步之后被钉回 `u=1, v=0`，它们不参与反应。

`bc="dirichlet"` 但 `fixed_mask` 全为空时，行为**等价于** `noflux`；求解器会记下这条注记，
因为这种静默等价以前造成过误读。

`core/gs.py` 另有一个 `fixed_mask`：内部被钉住的 Dirichlet 补丁（周期性域的"新鲜介质"点）。
它每步重新施加。

## 5. 观测量（`gs.metrics`）

每次采样记录：

| 字段 | 含义 |
|---|---|
| `Mv` | `h² Σv`，v 的总质量 |
| `vmax`, `vmin`, `umin`, `umax` | 极值，健康检查也用 |
| `active_area` / `active_area_cells` | `{v > thr}` 的面积 / 元胞数（默认 `thr=0.05`） |
| `Rg` | 以 v 为权的回转半径（对 `{v>thr}` 计算） |
| `cy`, `cx`, `centroid` | v 权重心 |
| `elongation` | 二阶矩比，用于跟踪形状拉长 |
| `components` | `{v > thr}` 的 4-连通分量数 |
| `reaction_flux` | `h² Σ u v²`，反应通量 |
| `resource_target_*` | 当前 `u_res` 的均值/最小/最大 |

**没有结构时形状量取 `None`，不取 0。** `vmax == 0` 或 `active_area == 0` 时
`Rg`/`centroid` 在数学上没有定义，报 0 会让下游把它当成"一个位于原点的点"。

## 6. 健康检查与"这条轨迹能不能用"

`FieldSolver._health()` 在每步之后检查：非有限值、负浓度、过冲（`v>5` 或 `u>5`）。
失败立即停止并把原因写进 `anomalies`。

调用方**必须**用 `usable(planned_time)` 判断，而不是相信末态：

```python
ok, why = s.usable(T)
# 失败时 s.t 停在最后一次健康时刻，此时任何位移/质量差都可能是假的
```

这条规则来自一个具体教训：一条健康检查失败的运行，其 trace 只包含 `t=0`，
于是"质心位移"平凡地为 0，被当成了"结构没有移动"的测量结果。

### 6.1 负浓度阈值是尺度相关的，失败是粘性的

健康检查不把"任何负值"都当成失败。FFT 路径的舍入地板远高于 float64 eps，
所以阈值取 `1e-5 * max(1, dt) * max(1, |u|max, |v|max)`（可用构造参数 `neg_tol` 覆盖）。
一个量级 `O(0.01)` 的真实失稳仍然会被抓到。

**失败是粘性的**：一旦记下 anomaly，后续 `step()` / `run_until()` 直接返回 `False`，
不再推进。这条规则来自一个具体教训——非粘性的实现在失败后仍可被驱动继续积分，
于是"已经判定不健康的状态"被一路推成了一条看起来像结果的长轨迹。

## 7. 平台相关的两个坑

1. **C kernel 的加载。** `core/solver.py` 在需要时用 `cc -O3 -shared -fPIC` 编译 `solver.c`，
   在 macOS 上再做 ad-hoc 签名（`codesign -f -s -`），否则启用库校验的解释器无法映射这个未签名 dylib。
   如果加载失败，自动退回 numpy 路径，`backend()` 会如实返回 `"c"` 或 `"numpy"`。
   `GS_NUMPY=1` 强制 numpy 路径。

2. **解释器 re-exec。** 如果仓库里存在 `.venv/bin/python`，而当前解释器不是它，
   `core/solver.py` 在 import 时会透明地 re-exec 进去。设 `GS_NO_REEXEC=1` 可禁用。
   这个 hack 存在是因为捆绑的运行时启用了库校验、拒绝加载本项目的 C kernel。

`core/gs.py` 不依赖 C kernel，因此没有这两个坑。
